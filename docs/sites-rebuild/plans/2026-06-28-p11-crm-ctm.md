# Phase 11 — CRM integration + CTM install

**Goal:** Wire up two CRM-adjacent layers that unlock the full lead-capture and phone-tracking
loop for provisioned sites:

1. **CTM (CallTrackingMetrics)** — per-site account ID stored on `sites`, script injected in the
   HTML `<head>` before the bundle, a `PhoneNumber` block that never re-renders after mount, and a
   route-change hook scaffold for when tenant SPA nav is added.

2. **CRM HTTP client** — a 5-endpoint integration to `anchor-hub` (provision / update / deprovision
   a site, list tracking numbers, list campaigns); a `crm_form` block that renders the CRM's
   inline-HTML embed so PHI never touches the builder; a Studio "Integrations" tab showing the CRM
   link and the site's tracking numbers.

Both tracks follow the env-driven mode-switch pattern already used by email (`send.ts`), AI
(`client.ts`), DNS (`resolve.ts`), and auth (`studio-auth.ts`): real credentials → real call,
absent + dev → stub, `*_DISABLED` → no-op. No secrets in source control.

## Design decisions

### D-052 — CTM per-site config and PhoneNumber block

**Context:** Architectural anchor #5 requires the CTM script in `<head>` before bundle JS, and
anchor #5b requires `<PhoneNumber>` to be `React.memo(() => true)` so CTM's DOM swap never gets
clobbered by a re-render.

**Decision:**
- `ctm_account_id TEXT` column on `sites` (nullable; NULL = CTM not installed for this site).
  Surfaced via `ResolvedSite.ctm_account_id`.
- `shell()` in `render-page.tsx` emits the CTM loader script immediately after `<style>` and
  before `headExtra` when `site.ctm_account_id` is set:
  ```html
  <script src="https://cdn.calltracking.com/call-tracking.min.js"
          async
          data-ctm-account-id="<escaped-id>"></script>
  ```
  Helper: `ctmScriptTag(accountId: string): string` (unit-tested for attribute escaping).
- `PhoneNumber` block (`type: "phone_number"`, in `@anchorcorps/components`):
  - Props: `{ number: string; display?: string }` (Zod schema validates E.164-ish format).
  - Component: `React.memo(() => "<a href='tel:…'>{display ?? number}</a>", () => true)` —
    the `() => true` comparator prevents any re-render after mount per D-009.
  - In the Puck editor preview: renders as a static text badge (no `tel:` link, no CTM swap).
- Route-change hook: `src/server/ctm-hook.ts` exports `runCtmNow()` — calls
  `window.__ctm?.main?.runNow()` with a null guard. This is a no-op scaffold; tenant-facing SPA
  navigation is not yet wired (renderer is SSR-only in P11). Document the wiring point.

### D-053 — CRM HTTP client, crm_form block, and 5-endpoint contract

**Context:** D-004 says the CRM is `anchor-hub`; integration is exactly 5 HTTP endpoints.
D-006 says forms are CRM embeds rendered as inline HTML — PHI never touches the builder.

**Decision:**

**CRM client** — `src/server/crm/client.ts`:
- Interface `CrmClient` with 5 methods corresponding to the 5 endpoints:
  1. `provisionSite(siteId, name, primaryDomain)` → `{ crmSiteId: string }` (`POST /sites`)
  2. `updateSite(crmSiteId, patch)` → void (`PATCH /sites/:id`)
  3. `deprovisionSite(crmSiteId)` → void (`DELETE /sites/:id`)
  4. `listPhoneNumbers(crmSiteId)` → `PhoneNumber[]` (`GET /sites/:id/phone-numbers`)
  5. `listCampaigns(crmSiteId)` → `Campaign[]` (`GET /sites/:id/campaigns`)
- `resolveCrmClient(env)` mode-switch (`src/server/crm/resolve.ts`):
  - `CRM_BASE_URL` + `CRM_API_KEY` present → `HttpCrmClient` (Bearer auth).
  - Absent + `NODE_ENV !== production` → `StubCrmClient` (log-only, returns empty data).
  - `CRM_DISABLED=true` → `NullCrmClient` (silent no-op — for prod installs that haven't
    provisioned the CRM yet).
- Injectable `fetch` argument for tests (same pattern as `GoDaddyDnsProvider`).

**crm_site_id storage:** `crm_site_id TEXT` column on `sites` (nullable). Populated by the
provision call in `createSiteWithDomains`. Enables the Studio "Integrations" tab to deep-link
into `anchor-hub` and to call `listPhoneNumbers`/`listCampaigns`.

**`crm_form` block** (`type: "crm_form"`, in `@anchorcorps/components`):
- Props: `{ embed_code: string; label?: string }`.
- SSR renderer: `dangerouslySetInnerHTML={{ __html: embed_code }}` inside a `<div>`. The embed
  code is operator-authored content from the anchor-hub CRM — no user-submitted data passes
  through the builder (D-006). Rendered outside React's event system, so no `<form>` inside
  React artifacts (architectural anchor #7 compliant).
- Puck editor preview: renders a styled placeholder card (`[CRM Form: {label}]`) with no
  `dangerouslySetInnerHTML` — prevents form-in-editor violations.
- Zod schema: `embed_code` is `z.string().min(1)`, no other validation (builder is not
  responsible for embed content).

## Operator prereqs (build proceeds without them; flag in the PR if blocking a live cutover)

- `CRM_BASE_URL` and `CRM_API_KEY` in Secret Manager (`anchor-hub-480305`) on the
  `anchor-sites` Cloud Run service. Use the append-not-replace `--set-secrets` pattern
  (shared-secret gotcha documented in `docs/domains.md`).
- Per-site `ctm_account_id` values — entered in the Studio SettingsTab after deploy.
- `anchor-hub` must expose the 5 CRM endpoints on `CRM_BASE_URL`. P11 implements the
  builder's side of the contract; the CRM-side API is a separate operator prereq.
