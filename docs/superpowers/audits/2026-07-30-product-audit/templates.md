## Chain verification (end-to-end, in code)

Authored `TemplateSeed` → `allTemplates` (index.ts) → `seedTemplates` validates every block against the live registry (`validateAllTemplates`, seed-templates.ts:82-93), UPSERTs `templates` by slug, DELETE+INSERT `template_pages` (196-218) → `GET /api/templates?kind=site` (`listTemplates`, repo.ts:153-180, ordered sort_order asc, name asc) → NewSitePage gallery (name ✓, description ✓, category chip ✓, cover_image_url ✓) → `POST /api/sites/from-template` → `TEMPLATE_MATERIALIZE` job copies pages verbatim (blocks, seo, title, slug) + adopts brand_tokens when site has none ✓.

**Fields that leak out of the chain:** page `sort_order` (authored, stored, DROPPED at materialize — `pages` has no ordering column, migration 1747571000000 lines 59-81); cover `alt` (authored types.ts:38, stored on media_assets, gallery hardcodes `alt=""` NewSitePage.tsx:85); `pages_count` (fetched/typed NewSitePage.tsx:45, never rendered); `brand_tokens` (never visualized pre-create); template→site provenance (nothing records which template a site came from). The known gap is confirmed: **no template preview or detail view exists anywhere** — the gallery card is the terminal surface; `GET /api/templates/:id` has zero admin-UI consumers.

## Directives

- [D700] (all 10 content templates) × (Content-quality/Honesty) — «A template must not ship an interactive element wired to an endpoint that does not exist». Instance: every `crm_form` posts into the void — `/api/leads` (home-services.ts:667, law-firm.ts:671, coaching.ts:488, nonprofit.ts:640, smb-landing.ts:403), `/reservations` (restaurant.ts:588), `/inquiries` (creative-portfolio.ts:388), `/special-orders` (local-retail.ts:420), iframes/posts to fictional domains `forms.willowbrookdental.com` (dental-practice.ts:434,493) and `forms.pulsefitnessdenver.com` (fitness-studio.ts:465); no such route exists anywhere in `src/server/routes/`, so every materialized site's lead capture 404s or DNS-fails on submit. Fix-class: one real platform lead endpoint templates may target, or a must-replace placeholder convention the AI agent is required to resolve.
- [D701] (NewSitePage + chain) × (Provenance→Consumption/Honesty/Comprehension) — «The gallery must show what the buyer actually gets». Instance: cover is a Pixabay stock photo picked by search query (seed-templates.ts:139-154), not a render of the template; no preview/detail view exists at all — `GET /api/templates/:id` (templates.ts:496-511) has zero UI consumers; NewSitePage.tsx:339-360 card is the terminal surface. Fix-class: render-derived cover (screenshot the materialized home page via the existing preview route) and/or a detail view listing the template's pages.
- [D702] (materialize-template.ts) × (Structure/Grain) — «Authored page order must survive materialization». Instance: `TemplatePageSeed.sort_order` (types.ts:23) is stored in template_pages but dropped at materialize (materialize-template.ts:70-74) because `pages` has no ordering column (migration 1747571000000:59-81) — site nav order falls back to insertion accident. Fix-class: `sort_order` column on `pages`, populated from the template.
- [D703] (NewSitePage + materialize) × (State-Visibility/Failure-Recovery) — «A failed materialization must be visible and retryable». Instance: the from-template response reports `job:{queued:false,error}` (templates.ts:435-441) but NewSitePage.tsx:189-196 reads only `site.id`, polls 8s, and silently lands the operator on a 0-page site; no retry affordance exists anywhere. Fix-class: check `job.queued` in the client, surface the error, add a re-enqueue action.
- [D704] (routes/templates.ts + jobs/index.ts) × (Contract-Stability) — «A claimed dedupe must actually dedupe». Instance: `singletonKey: siteId:templateId` (templates.ts:114-120, "D-042") is inert because `TEMPLATE_MATERIALIZE` is created without `{ policy: "stately" }` (jobs/index.ts:171) — the same file documents this exact pitfall (jobs/index.ts:185-191) and fixes AGENT_TURN, GIT_EXPORT, GIT_IMPORT, SITE_PROVISION but not this queue; only handler idempotence masks it. Fix-class: `boss.createQueue(TEMPLATE_MATERIALIZE, { policy: "stately" })`.
- [D705] (10 content templates) × (Structure/Grain) — «Site chrome must not be N per-page copies». Instance: nav-bar + rich-footer are duplicated as literal blocks on every page (e.g. home-services.ts repeats an identical 30-line footer 5×); post-materialize, one nav edit means editing every page, and per-page drift is unguarded. Fix-class: site-level chrome (shared nav/footer outside page blocks) or a chrome-sync mechanism.
- [D706] (starter.ts, dental-practice.ts) × (Content-quality) — «An authored anchor must have a target». Instance: starter home CTA `#contact` (starter.ts:32) targets nothing on any page; dental `#new-patients-forms` (dental-practice.ts:390) targets a block id, but the prod BlockRenderer wraps blocks in a bare Fragment with no DOM id (BlockRenderer.tsx:82) so no `#block-id` anchor ever resolves. Fix-class: emit `id={block.id}` on the prod wrapper (cheap) and fix starter's href.
- [D707] (materialize + DB rows + seed) × (Temporal-Integrity/Provenance) — «A site must know which template (and which version of it) it came from». Instance: materialize records nothing on the site (no `sites.template_id`; only `page_revisions.source='import'`), while `deploy:db` re-seeds templates on every deploy (package.json:18), mutating the gallery in place with no version stamp — template-vs-derived-site drift is unknowable by construction. Fix-class: `sites.template_id` + a content hash/version on templates rows.
- [D708] (seed-templates.ts) × (Reversibility/Safety) — «Environments must not share a mutable storage namespace». Instance: the live bucket holds two complete cover sets under two different system-site UUIDs (`variants/2cac5ca8-…` 19:35Z, `variants/cd01c14a-…` 00:40Z) — two databases seeding into the one prod bucket `anchorcorps-media`; one set is orphaned from whichever DB serves studio, and local seeding writes into prod storage. Fix-class: env-scoped bucket or key prefix (MEDIA_BUCKET is already env-var; enforce a non-prod default).
- [D709] (nonprofit.ts) × (Precondition/Forward-path) — «A conversion CTA must lead to a working conversion path». Instance: "Donate Now" (nav cta nonprofit.ts:78-80, announcement :84-91, two CTA blocks) all route to `/get-involved`, which contains no donation mechanism of any kind — the template's primary ask dead-ends at a contact form. Fix-class: a donate-link slot (external processor URL) or copy that doesn't promise "Donate Now".
- [D710] (all 10 content templates; worst: nonprofit, home-services) × (Honesty) — «Fabricated legal/identity artifacts must not be indistinguishable from real ones». Instance: fake EIN "54-2093817" as 501(c)(3) fine print (nonprofit.ts:188 ×5 footers), fake "Ohio Lic. #OH-48219" (home-services.ts:181 ×5), fabricated $85M results/credentials (law-firm.ts:513), and real-platform social URLs for fictional handles (facebook.com/ironcladhomeservices etc., every template) — all ship verbatim if the operator doesn't hand-edit five footers. Fix-class: unmistakable placeholder markers (e.g. "EIN 00-0000000") + an agent must-replace manifest per template.
- [D711] (9 content templates) × (Temporal-Integrity) — «Template copy must not carry dates that rot». Instance: "First Friday Listening Party — August 7" (local-retail.ts:297), "complimentary whitening … this month" (dental-practice.ts:108), "booking into Q1 2027" ×3 (creative-portfolio.ts:80,176,352), "© 2026" in every footer — all frozen at authoring time and stale on any site created later. Fix-class: strip dated promos from seeds; render copyright year dynamically or flag perishable fields.
- [D712] (dental-practice.ts, local-retail.ts) × (Honesty) — «A finished-looking template must not contain permanently empty slots». Instance: bare `image` blocks with alt text but no asset (dental-practice.ts:481-487, local-retail.ts:324-330) render an empty placeholder box forever on the materialized site. Fix-class: remove them, or extend the cover-style stock-resolution pipeline to in-page images at seed time.
- [D713] (local-retail.ts) × (Content-quality) — «Empty-string CTAs are placeholder artifacts, not content». Instance: hero `cta_label:"" cta_href:"#"` (local-retail.ts:309-310, 363-364) and split-hero `secondary_cta_label:"" secondary_cta_href:"#"` (:171-172) lean on component defensiveness instead of omitting the optional fields. Fix-class: omit the props; make schemas treat empty-string as absent.
- [D714] (types.ts + NewSitePage) × (Provenance→Consumption) — «Every authored field must reach a surface or be cut». Instance: cover `alt` (types.ts:38) is carefully authored per template but the only surface that shows covers hardcodes `alt=""` (NewSitePage.tsx:85); `pages_count` is fetched and typed (NewSitePage.tsx:45) but never rendered. Fix-class: `alt={t.name}`-at-worst plus a "N pages" line on the card.
- [D715] (index.ts + NewSitePage) × (Organization) — «A category axis that is 1:1 with items organizes nothing». Instance: 11 templates carry 11 distinct categories (Basic/Medical/Home Services/Restaurant/Legal/Fitness/Portfolio/Coaching/Nonprofit/Retail/Business) and the gallery neither groups, filters, nor searches by category — it renders as a per-card chip only (NewSitePage.tsx:355). Fix-class: group the grid by category (or collapse categories to a few real ones) before the library grows past one screen.
- [D716] (materialize + from-template route) × (Precondition/Forward-path) — «Don't provision a public hostname for a site that serves nothing». Instance: from-template auto-enqueues `site.provision` for the canonical hostname (templates.ts:421-430) while every materialized page lands as `status='draft'` (materialize-template.ts:70-74) and the tenant route serves only `status='published'` (page.ts:38) — a fresh template site 404s publicly with no publish step anywhere in the create flow. Fix-class: publish-on-materialize option, or a visible "your site is draft-only" state + bulk publish affordance.
- [D717] (starter.ts) × (Sibling-Coherence) — «Every registered template meets the same bar». Instance: starter is the only template with no test file (all ten siblings have `<slug>.test.ts`) and the only one in placeholder voice ("Replace this copy…") while siblings are fully-produced fictional businesses — the gallery gives no signal which philosophy a card follows. Fix-class: add starter.test.ts; mark starter's description as a bare-bones skeleton.
- [D718] (restaurant.ts) × (Content-quality) — «Fictional copy must be internally consistent». Instance: "opened … in the fall of 2019 … A decade later, the fire's still going" (restaurant.ts:338) — 2019→2026 is seven years. Fix-class: copy edit.
- [D719] (creative-portfolio.ts + block registry) × (Population/Dark) — «Every registered block must be authorable». Instance: `logo-reel` requires non-empty `logos[].src` URLs so no template can use it (documented at creative-portfolio.ts:29-32) — a registry block that the authoring format cannot exercise, dark across the whole catalog. Fix-class: accept asset_id/stock_query in logo-reel, or record its dark status deliberately.
- [D720] (seed-templates.ts) × (Idempotence/Accretion) — «Editing an authored field must propagate on reseed». Instance: changing a template's `cover.stock_query` does nothing while `cover_image_url` is non-null (skip at seed-templates.ts:129-137); the documented remedy is hand-run SQL (:48-52). Fix-class: persist the resolved source query beside the URL and re-resolve when it differs.
- [D721] (routes/templates.ts) × (Terminality) — «Catalog curation must have a surface». Instance: archive exists (`DELETE /api/templates/:id`, templates.ts:517-532) but no admin UI calls it — NewSitePage is the sole `/api/templates` consumer — so retiring, reordering, or inspecting catalog entries is curl-only. Fix-class: minimal templates admin list with archive toggle.
- [D722] (smb-landing.ts, local-retail.ts) × (Naming/Least-astonishment) — «Slug, display name, and category should tell one story». Instance: slug `smb-landing` / name "SMB Consulting" / category "Business" (smb-landing.ts:81-95) disagree about what the template is; local-retail nav labels "Shop" but routes `/shop-info` (local-retail.ts:29). Fix-class: align names before the catalog is public.
- [D723] (all 10 content templates) × (Sibling-Coherence) — «One icon language per catalog». Instance: feature-grid `icon` values split three ways — named SVG glyphs ("shield"/"bolt": home-services, law-firm, fitness, smb, nonprofit), emoji ("🦷"/"🔥": dental, restaurant, coaching, local-retail), and literal strings rendered verbatim ("01"-"04", "◆", "1"-"4": creative-portfolio, dental new-patients) via the verbatim fallback (icons.tsx:10-14) — visibly different visual languages across cards in the same product. Fix-class: pick one convention in the template-authoring guide and sweep.
- [D724] (restaurant.ts, fitness-studio.ts, local-retail.ts, starter.ts) × (Sibling-Coherence) — «Module conventions should not fork silently». Instance: 7 of 11 templates ship `export default`; these four don't (index.ts imports named exports, so both work) — trivial, but exactly the kind of fork that spreads. Fix-class: one convention, lint or guide note.
- [D725] (index.ts + seed-templates.ts) × (Terminality) — «Deregistering a template must have a story». Instance: seeding is additive-only — removing a template from `allTemplates` (index.ts:21-33) leaves its DB row live and gallery-visible forever; no reconcile step archives rows absent from the registered set. Fix-class: after the upsert loop, archive built-in-origin rows whose slug is no longer registered (or document the manual step).
